Keep useful work when a search is interrupted.

If a search fails or the connection ends, completed results should stay useful. The backend should report what it observed, preserve recorded usage, and keep its work slot occupied until the actual search ends.

      What this ticket will accomplish
      
    
      
      
      Preserve an honest account
        
        
      • Keep completed stage details and validated rerank candidates when later work fails.
        • 
        
      • Distinguish an actual failure from work whose outcome became unknown.
        • 
        
      • Freeze published results and observed metrics; record later model usage under the same request ID.
        • 
        
      • Return safe public errors and one sanitized operational record per HTTP request.
        • 
      
      
      
      Keep resource ownership correct
        
        
      • Use one response deadline from admission, including time spent across all stages.
        • 
        
      • Keep both question routes busy until the actual worker finishes.
        • 
        
      • Detach an absent observer and discard later events. Bound the event queue to 64 entries.
        • 
        
      • Observe late worker exceptions, recover the slot, and wait for active work during shutdown.
        • 
      
      
    
      
  
      

  
      
    
      The implementation focus
      
    
      Much of the core behavior is already present. The remaining work is to prove the full lifecycle contract and correct any gaps those checks expose.
      
    
        
      
      • Slow or absent consumers. Exercise queue exhaustion and transport failures without blocking or cancelling the search.
        • 
      
      • Competing terminal outcomes. Test completion near the deadline and verify that a healthy connected run gets exactly one terminal event with no later application events.
        • 
      
      • Work after observation ends. Verify retained results, immutable metrics, late cost records, eventual exceptions, and slot recovery on both routes.
        • 
      
      • Operational evidence. Extend deterministic mocked HTTP checks for failures, disconnects, cancellation, sanitized logs, and shutdown with active work.
        • 
    
      
  
      

  
      
    
      Scope boundaries
      The ticket covers the NASA RAG backend. Browser presentation, retry buttons, proxy integration, and deployment remain separate work.
      It adds no automatic retries, replay, saved search history, job queue, or separate rate allowance. A manual retry is a fresh request and may receive a busy response while earlier work continues.
      
    
      Ready when
      Every acceptance criterion in ticket 05 has evidence, including the interruption cases above. Focused tests, type checks, and the full regression suite pass; the implementation is reviewed and committed.
      Ticket 06 then verifies and documents the complete stream contract before frontend integration is declared ready.
