# Domain docs

This repo uses one domain context: `GLOSSARY.md` at the repo root and architecture decisions under `docs/adr/`.

## Before exploring an area

- Read `GLOSSARY.md` for the project's terms.
- Read ADRs under `docs/adr/` that concern the area being explored.
- If these files do not exist, proceed silently. The domain-modeling skill creates them when a term or architectural decision is actually resolved; setup does not create placeholders.

## Vocabulary

Use the glossary's terms in tickets, specs, and technical discussions. If a needed concept is missing, reconsider the wording or note the gap for domain modeling.

## Architectural decisions

Respect relevant ADRs. If a proposed change conflicts with one, identify the decision and explain the conflict rather than silently overriding it.
